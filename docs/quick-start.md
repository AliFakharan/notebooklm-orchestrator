# شروع سریع — راه‌اندازی روی دستگاه خودت

این راهنما کل مسیر را می‌پوشد: نصب، اجرای نسخه‌ی نمایشی (mock)، و بعد حالت زنده
(درخواست واقعی به NotebookLM از حساب گوگل تو). **کاربر و توکن وجود ندارد**؛ اپ
تک‌کاربر است و فقط روی `127.0.0.1` گوش می‌کند، یعنی فقط تو روی همین دستگاه می‌توانی
به آن دسترسی داشته باشی.

## پیش‌نیازها

| چیز                          | نسخه   | چه‌کار می‌کند                               |
| ---------------------------- | ------ | ------------------------------------------- |
| Node.js                      | ≥ 22.5 | اجرای سرور و وب                             |
| Python 3                     | 3.10+  | فقط برای حالت زنده (کارگر `notebooklm-py`)  |
| مرورگر Chrome/Edge روی سیستم | —      | برای گرفتن کوکی‌های حساب گوگل               |
| Docker (اختیاری)             | —      | اگر دوست داری بدون نصب Node/Python اجرا کنی |

---

## ۱) نصب و اجرای سریع (حالت نمایشی)

حالت پیش‌فرض **mock** است: هیچ درخواست واقعی نمی‌رود، خروجی‌ها شبیه‌سازی‌شده‌اند و
روی همه‌ی آن‌ها برچسب mock می‌بینی. برای آشنا شدن با اپ عالی است.

```bash
git clone <repo> && cd notebooklm-orchestrator
npm install
npm run build        # وب را build می‌کند
npm run start --workspace @nlo/server
```

سپس مرورگر را روی **http://127.0.0.1:4870** باز کن. تمام — نه کاربر، نه رمز، نه
توکن.

> برای توسعه (تغییرات زنده): `npm run dev` — سرور روی 4870 و Vite روی 5173.

## ۲) حالت زنده — درخواست واقعی به NotebookLM

پنج مرحله‌ی یک‌بار:

### مرحله‌ی ۱ — کارگر پایتون

```bash
npm run worker:setup --workspace @nlo/server
```

این دستور `data/venv` می‌سازد و داخلش `notebooklm-py` را نصب می‌کند
(تنها دسترسی شبکه‌ی این مرحله، PyPI است). مرورگر موردنیاز نیست: ورود حساب‌ها
با چسباندن کوکی‌های نشستِ گوگل از مرورگر عادی شما انجام می‌شود.

### مرحله‌ی ۲ — باینری Xray

خروجی‌های گوگل باید از طریق نود VLESS تو برود؛ تانل با Xray ساخته می‌شود.

```bash
# باینری رسمی xray را در data/vendor/xray/xray بگذار (chmod +x هم بده)
# فایل‌های geoip.dat / geosite.dat کنارش اگر نداری، از همان ریلیز رسمی
```

> تا وقتی Xray نباشد، runtime به‌جای شکستن، «not_configured» گزارش می‌دهد
> (fail-closed) و اپ قابل استفاده برای mock می‌ماند.

### مرحله‌ی ۳ — `.env`

```bash
cp .env.example .env
```

و در `.env` این سه خط را فعال/تکمیل کن:

```ini
NLO_PROVIDER=python-worker
NLO_PROXY_RUNTIME=xray
NLO_PYTHON_BIN=$PWD/data/venv/bin/python
```

### مرحله‌ی ۴ — راه‌اندازی

```bash
npm run start --workspace @nlo/server
```

لاگ استارت می‌گوید همه‌چیز فعال است:
`provider=python-worker proxyRuntime=xray`.

### مرحله‌ی ۵ — اتصال حساب گوگل + نود VLESS (در UI)

**حساب:**

1. «حساب‌ها» ← «افزودن حساب» و ایمیل گوگل خودت را بنویس (ایمیل هویت
   حساب است و باید یکتا باشد).
2. در مرورگر عادی خود وارد `notebooklm.google.com` شو، کوکی‌های نشست گوگل را
   با افزونه‌ی «کپی کوکی‌ها» کپی و در دکمه‌ی **«کوکی‌های مرورگر»** همان ردیف
   بچسبان (storage-state JSON یا آرایه‌ی کوکی).
3. دکمه‌ی **«تأیید جلسه»** → verify واقعی در برابر سرویس گوگل؛ وضعیت حساب
   می‌شود **AUTHENTICATED / verified** و هویت گزارش‌شده باید با ایمیل حساب
   یکی باشد.

**نود:**

1. «پراکسی‌ها» ← URI صحنه‌ی `vless://…` را بچسبان (تک‌تکی یا چندتایی از
   کلیپ‌بورد).
2. «تست پینگ همه نودها» → نود باید «پاسخ داد» را نشان دهد.

**اولین درخواست واقعی:**

1. «درخواست جدید» ← **انتخاب حساب** (الزامی) ← سؤال (و صوت/نکته‌بندی اگر
   خواستی) ← «ایجاد».
2. صف: `WAITING_FOR_PROXY` → `RUNNING` → `SUCCEEDED`.
3. در جزئیات درخواست، برچسب `resultProvenance: real` یعنی خروجی واقعاً از
   NotebookLM آمده (نه mock).

## ۳) با Docker (بدون نصب Node/Python روی سیستم)

یک کانتینر که همه‌چیز را (سرور + وب buildشده) دارد:

```bash
docker compose up --build -d
```

و مرورگر روی **http://127.0.0.1:4870**.

نکات حالت زنده با Docker:

- **`.env`**: compose مقادیر `NLO_*` را از `.env` همین پوشه **داخل** envهای
  کانتینر می‌کوبد — همان فایل که حالت بدون-Docker می‌خواند. برای حالت زنده دو
  خط کافی است: `NLO_PROVIDER=python-worker` و `NLO_PROXY_RUNTIME=xray`
  (و بعد `docker compose up -d` دوباره). `NLO_PYTHON_BIN` را برای Docker
  در `.env` بنویس — compose مقصداً آن را روی venvِ داخل تصویر
  (`/opt/nbl-venv/bin/python`) قفل می‌کند؛ اگر مسیر **هاست** را در `.env`
  بزنی (مثل حالت بدون-Docker) داخل کانتینر وجود ندارد و spawn می‌شکند.
  (compose همچنین `NLO_HOST=0.0.0.0` را داخل کانتینر می‌گذارد — برای
  پورت‌فوروارد Docker لازم است؛ چون فقط loopbackِ هاست expose می‌شود، امن
  می‌ماند.)
- **Xray**: باینری + geo فایل‌ها در `./data/vendor` بگذار (volume مشترک است).
  ⚠️ بدون `ca-certificates` تصویر، xray همه‌ی TLSها را «unknown authority»
  می‌کند — این بسته در Dockerfile نصب شده؛ اگر تصویر را دستی تغییر می‌دهی
  آن را حفظ کن.
- **Python worker**: حالا **خودِ تصویر** Python دارد (venv در `/opt/nbl-venv`
  با `notebooklm-py[browser]`) — یعنی حالت زنده بدون هیچ تنظیمیِ اضافی
  کار می‌کند. نیازی به `NLO_PYTHON_BIN` در `.env` نیست.
- **محدودیت شبکه**: اگر داکر روی هاستت به registry/اینترنت عمومی دسترسی ندارد
  (مثلاً فقط mirror registry)، build اول `node_modules` و `dist` هاست را می‌خورد
  و کار می‌کند (Dockerfile اینطور طراحی شده).
- **ورود با Docker / سرور headless**: چون ورود فقط با **چسباندن** کوکی است،
  نیازی به مرورگر روی خود سرور نیست — کوکی‌ها را روی دستگاه شخصی‌تان از
  مرورگر خود کپی کنید و در UI سرور بچسبانید؛ verify واقعی انجام می‌شود.

## ۴) روزمره

| نیاز          | راه                                                                                  |
| ------------- | ------------------------------------------------------------------------------------ |
| استارت        | `npm run start --workspace @nlo/server` یا `docker compose up -d`                    |
| وضعیت         | `curl http://127.0.0.1:4870/api/health`                                              |
| قطع           | `docker compose down` یا Ctrl-C / `kill` روی فرآیند                                  |
| داده‌ها       | همه‌چیز در `data/` است (SQLite، آرشیو شغل‌ها، vault، کوکی‌ها). بکاپ = کپی همین پوشه. |
| پاک‌کردن کامل | `data/` را حذف کن؛ دوباره از مرحله‌ی ۱.                                              |

## ۵) اگر حساب «منقضی» شد

کوکی‌های گوگل عمر محدود دارند (معمولاً چند روز تا چند هفته، بسته به فعالیت).
وقتی وضعیت حساب **EXPIRED** شد: دوباره «کوکی‌های مرورگر» → چسباندن →
verify → AUTHENTICATED. شغل‌های FAILED پس از آن با دکمه‌ی «بازتلاش» دوباره
وارد صف می‌شوند (با انتخاب پراکسی تازه).

## ۶) اگر چیز عجیبی دیدی

- `provider=python-worker` ولی خطای `worker failed to start` → در حالت بدون-Docker
  `NLO_PYTHON_BIN` را چک کن (مسیر دقیق `…/data/venv/bin/python`). در حالت Docker
  این خطا نباید بیاید چون venv داخل تصویر است؛ اگر دیدی، `docker compose up --build -d`
  بزن تا تصویر تازه ساخته شود.
- نود «پاسخ نداد» → URI را دوباره چک کن، یا «تست پینگ» روی همان ردیف؛
- درخواست در `NEEDS_ATTENTION` گیر کرد → یعنی خطای مبهم وسط عملیات غیرقابل‌تکرار
  بود؛ از دکمه‌ی «دوباره در صف» پیش برو؛
- جزئیات امنیت (چرا loopback، کوکی‌ها کجا، vault): [`security.md`](security.md).
